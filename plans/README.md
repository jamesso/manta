## Rules for every plan

- **Branch:** one long-lived branch `upgrade/electron-45`. Each plan is a series of commits on it. Commit subject: short and imperative, no prefix, no AI attribution (example: `Migrate tests from Jest to Vitest`). Do not push unless the operator says so.
- **Package manager:** npm (Yarn is not installed). Node 24 (`.nvmrc`).
- **Data safety (most important):** user data is in `~/Library/Application Support/Manta` (macOS). Invoices and contacts are in IndexedDB under the `file://` origin (`IndexedDB/file__0.indexeddb.leveldb`). Settings are in the JSON file `Settings`.
  - Never run a dev or test build against that folder. Before any manual check, copy it: `cp -R "$HOME/Library/Application Support/Manta" /tmp/manta-profile-copy`.
  - After plan 002, run the built app on the copy: `MANTA_USER_DATA=/tmp/manta-profile-copy npm start`. Without the variable, dev runs use `appData/Manta-dev`.
  - Production windows must keep loading over `file://` (`loadFile`). A change of origin makes all saved invoices invisible.
  - Keep `productName: Manta`, because the user-data path depends on it.
- **Verification:** each plan lists the exact commands. GUI checks are manual smoke steps on a data copy.

## Dependency notes

- **001 before everything.** It gives a working install and a green test baseline on Node 24. The 2018 toolchain (Jest 22, Babel 6, webpack 4) does not install or run on Node 24. Electron 1.8 has no `darwin-arm64` binary and its npm postinstall ignores `ELECTRON_SKIP_BINARY_DOWNLOAD=1`, so plan 001 uses `ELECTRON_SKIP_BINARY_DOWNLOAD=1 npm install --ignore-scripts` and `npm ci --ignore-scripts` (not in `.npmrc`); plan 002 must run lifecycle scripts so the Electron 45 binary installs.
- **001 changes some renderer code.** It changes `require(...)` lines into `import` lines, because Vitest's `vi.mock` does not catch `require`. Only import, require and export lines change, and a grep in 001 checks this. 001 also removes Spectron, mocha, chai and pre-commit, because Spectron's chromedriver does not install on arm64. 001 keeps `test/` for plan 011. Plans 010 and 011 check whether a package is still installed before they remove it.
- **002 → 003:** 002 starts the app in compatibility mode with these parts:
  - `nodeIntegration` on, through the shared `COMPAT_WEB_PREFERENCES` constant in `helpers/windows.js`.
  - `@electron/remote`.
  - Renderer imports of `'electron'` aliased to the shim `libs/electron-renderer.js`.
  - The modal window moved to `main/modal-window.js`.
  - `electron-updater` 6, which the main process loads at startup.

  003 then fixes the main-process APIs that Electron removed: callback `printToPDF` and `showOpenDialog`, and `addDevToolsExtension`. It also moves settings to electron-store, which reads the existing `Settings` file. Renderers get the settings through `remote.getGlobal('mantaSettings')`.
- **004 → 005 → 006:**
  - React goes to 18.3 first, as React recommends. React 18.3 warns on every API that React 19 removes, and it still runs the old libraries.
  - Enzyme has no React 18 adapter, so 004 rewrites those tests with Testing Library. react-redux 9 needs React 18, so 005 comes after 004. `@hello-pangea/dnd` and `motion` also need React 18, so 006 comes after 004.
  - `.npmrc` with `legacy-peer-deps=true` is temporary. 001 creates it, and 006 deletes it after the last library pinned to React 16 is gone.
- **007 (PouchDB 9)** can technically run any time after 003. Run it after 006 to keep the order linear and to test data on a stable app. It must keep the `idb` adapter, or existing databases are not found.
- **008 after 006:** React 19 removes the legacy context and `defaultProps` support that the old UI libraries used.
- **009 after 008:** 009 edits the same components as 008. It removes these compatibility parts from 002/003:
  - `COMPAT_WEB_PREFERENCES` and `enableRemote`
  - `libs/electron-renderer.js` and the `electron` alias
  - `@electron/remote`
  - all `window.require` calls

  It also takes over `webUtils.getPathForFile` (from 006) through the preload bridge.
- **010 after 009:** the one-time Prettier 3 reformat commit comes last, so it does not conflict with the other plans. Its SHA goes into `.git-blame-ignore-revs`.
- **011 last.** It needs the final architecture (preload output, `out/**`, and `static/**` if 002 reads it through `app.getAppPath()`). **Operator input required:** the GitHub owner/repo to publish releases and updates to. Today `electron-builder.yml`, `dev-app-update.yml` and git `origin` all point to upstream `hql287/Manta`. 011 stops if no target is given. Signing and notarization need an Apple Developer ID and, optionally, a Windows code-signing certificate. Without them, 011 produces unsigned builds and reports that.

## Facts behind the plan

- Electron 45.2.0 (Chromium 156, Node 24.22) supports macOS 13+, Windows 10+, and 64-bit x64/arm64 only. Electron 45 has no 32-bit builds, so the `ia32` targets go. Electron 44 raised the macOS minimum to 13. Sources: [Electron 45 release](https://www.electronjs.org/blog/electron-45-0), [breaking changes](https://electronjs.org/docs/latest/breaking-changes), [rstudio#19063](https://github.com/rstudio/rstudio/issues/19063).
- Electron 1.8 has no arm64 build, so on Apple Silicon it runs only through Rosetta 2. The universal mac build in 011 removes that dependency.
- Package versions were checked on the npm registry on 2026-10-30/31. Each plan says to confirm the versions with `npm view <pkg> version` at execution time.

## Deviations the plan writers made from the first recommendations (already reflected in the plans)

- **ESLint 9.39.x, not 10** (plan 010): `eslint-plugin-react` 7.37.5 declares a peer range up to `^9.7`. Move to ESLint 10 when the plugin supports it.
- **No string refs exist.** The earlier count of 17 matched `href="#"`, so plan 008 does not migrate refs. Only 4 `defaultProps` sites are on function components (RecipientForm, Button, Message, Slide).
- **8 `translate()` HOC sites, not 10** (plan 005).
- **`react-addons-shallow-compare` is removed in 006, not 005,** because it is a peer of `react-dates` 12.

## Findings considered and rejected

- **Keep Electron 43 to support macOS 12:** rejected. Electron 43 stops getting security fixes when Electron 46 ships, so this only delays the migration.
- **Keep webpack (upgrade to webpack 5) instead of electron-vite:** rejected. It would need about 8 webpack and Babel plugins to replace react-hot-loader and Babel 6. electron-vite covers main, preload and renderer builds and Fast Refresh in one config.
- **Replace `moment` with date-fns or dayjs:** rejected for now. User settings store moment format tokens (for example `invoice.dateFormat = 'MM/DD/YYYY'`), so 006 upgrades moment to 2.31 instead.
- **Rewrite Redux code with Redux Toolkit:** rejected. It is not needed to run on current systems. `redux-actions` 3 still works with Redux 5.
- **Rewrite to TypeScript or function components:** out of scope. It adds no OS or dependency support.
- **Skip React 18.3 and go to 19 directly:** rejected. React 18.3 warns on every API that 19 removes, and it still runs the old libraries while they are replaced.
