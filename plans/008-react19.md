## Why this matters

React 18 gets no new features and its ecosystem is moving to 19 (current: 19.3.1). Manta's renderer still uses patterns from 2018. React 19 silently ignores `defaultProps` on function components, so four components would get `undefined` instead of their defaults — for example `RecipientForm` crashes on `formData` being `undefined`, and `Message` loses its default `info` style. React 19 still runs `componentWillMount` / `componentWillReceiveProps`, but they are deprecated "unsafe" lifecycles and print warnings; 12 of them hold the form's reset logic. This plan upgrades React and replaces both patterns with exact behavioral equivalents, with regression tests for each prop→state sync.

Reference: [React 19 Upgrade Guide](https://react.dev/blog/2024/04/25/react-19-upgrade-guide).

### Step 4: Replace `componentWillReceiveProps` with `componentDidUpdate`

Use this exact translation for each of the 7 methods. It keeps the old semantics: the old method ran only when the parent re-rendered (new props object), never after the component's own `setState`.

```js
// BEFORE
componentWillReceiveProps(nextProps) { BODY }

// AFTER
componentDidUpdate(prevProps, prevState) {
  // Same trigger as the old componentWillReceiveProps: parent re-render only
  if (prevProps === this.props) return;
  BODY  // with: nextProps → this.props, this.props → prevProps, this.state → prevState
}
```

Example for `Currency.jsx`:

```js
componentDidUpdate(prevProps, prevState) {
  if (prevProps === this.props) return;
  // Already made changes but not saved
  if (prevState !== prevProps.savedSettings) {
    // Reset to savedSettings if the below condition is met
    if (this.props.currency === this.props.savedSettings) {
      this.setState(this.props.savedSettings, () => {
        this.updateCurrencyState();
      });
    }
  }
}
```

Apply to: Discount, InvoiceID, Note, DueDate, Recipient, Currency, Tax. In `Recipient.jsx`, `Object.assign({}, this.state, …)` inside `setState` becomes `Object.assign({}, prevState, …)`.

Infinite-loop guard: each `setState` in these bodies is followed by a render with the **same** props object, so `prevProps === this.props` returns early. Do not remove that line.

**Verify**: `grep -rnE "componentWill(Mount|ReceiveProps|Update)\b" app preview modal tour --include='*.jsx' | grep -v __tests__` → no matches (`componentWillUnmount` is fine and is excluded by `\b` + the pattern). `npm test` → all pass.

- `prop-types` is now dead weight at runtime (React 19 ignores it). Deferred: delete `propTypes` blocks and the package in a later cleanup, or replace with TypeScript/JSDoc.
